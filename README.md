# 従業員・給与情報管理システム (HR & Payroll Management)

## 概要
バックオフィス業務（人事・給与計算ドメイン）を題材に、Web開発の基礎原則（HTTP通信、DBトランザクション、コンテナ仮想化）と実務的な設計思想を身につけるために制作したWebアプリケーションです。

単なるCRUD機能の実装にとどまらず、業務システムで必須となる「過去データのエビデンス保持（変更履歴の保護）」や「外部キー制約によるデータ不整合の防止」をデータベース設計に反映しています。

フレームワークの便利機能に頼る前に、Webアプリケーションの基盤動作（HTTPリクエスト/レスポンス、セッション管理、PDO接続）を根本から理解するため、あえて**ピュアPHP**を用いて構築しました。

---

## 本プロジェクトの目的・学習テーマ

1. **コンテナ仮想化技術（Docker）の実践**: 開発環境の差異を排除し、誰の環境でも即座に立ち上がる再現性の高い環境構築。
2. **実務を意識したGit運用の習得**: 直コミットを避け、ブランチ運用（GitHub Flow）とPull Requestベースの開発サイクルの実践。
3. **Webの基本原理・セキュリティの理解**: フレームワークが裏側で自動処理しているSQLインジェクション対策やXSS対策、DB接続プール/シングルトンの仕組みをコードレベルで実装。
4. **業務ドメインを考慮したDB設計**: 実際の業務（人事・税務・給与）で発生しうる「誤削除」や「過年度エビデンス確認」に耐えうるスキーマ設計の追求。

---

## システム構成 & アーキテクチャ

* **App Container**: PHP 8.2 / Apache
* **DB Container**: MySQL 8.0
* **ネットワーク**: Docker内部ネットワークによるDNS名前解決（ホスト名: `db`）
* **文字コード**: アプリケーション層・DB層ともに `utf8mb4` に統一（人名外字や絵文字などの文字化けを防止）

---

## こだわりと技術的判断

### 1. 業務の安全性を重視したDB設計
* **論理削除の採用 (`employees.deleted_at`)**
  * 従業員が退職・異動となった場合でも、過年度の給与計算根拠や税務関連の履歴照会（エビデンス確認）に備え、データを物理削除（DELETE）せず論理削除とする構成にしています。
* **意図的なカスケード削除の非採用 (`salaries` テーブル)**
  * 従業員情報の変更・削除操作によって、過去の確定した給与支給履歴が連動して消滅する事故を防ぐため、外部キー制約においてあえて `ON DELETE CASCADE` を設定せず、データの整合性を最優先に保護しています。

### 2. セキュリティ対策の徹底
* **SQLインジェクション対策**: PDOのプリペアドステートメント（プレースホルダー）を徹底し、入力値のエスケープ漏れによる不正なSQL実行を防止。
* **XSS（クロスサイトスクリプティング）対策**: 画面出力箇所すべてで `htmlspecialchars`（`ENT_QUOTES`, `UTF-8`）を通し、スクリプトの実行を無害化。

### 3. Docker & Git によるチーム開発を意識した運用
* **Dockerによる環境の共通化**: OS固有のミドルウェア依存を排除し、コマンド1つで同一の実行環境を構築可能に設計。
* **GitHub Flowを意識したブランチ運用**: 機能追加や不具合修正ごとにフィーチャーブランチを作成し、Pull Requestを通じてコード差分を意識しながらマージする運用を実施。

* Docker / Docker Compose がインストールされていること

## 今後の展望（フレームワーク移行計画）

ピュアPHPでの実装を通じて「ルーティング管理の煩雑さ」「ビジネスロジックとビューの結合」「CSRF対策などの共通処理の実装コスト」といった課題を体感しました。これを踏まえ、次のステップとして**Laravelを用いたリプレイス**を計画しています。

1. **Laravelフレームワークへのリプレイス**
   - MVCアーキテクチャによる関心の分離と保守性の向上。
   - CSRF保護ミドルウェアや標準バリデーションによる堅牢化。
2. **Laravel Sailの導入**
   - 公式のSail環境へ移行し、チーム開発におけるコンテナ構成のさらなる標準化。
3. **ORMとマイグレーションの活用**
   - 生SQLから `Eloquent ORM`（`SoftDeletes`）へ移行し、論理削除コードの共通化。
   - SQLファイルによる手動管理から、Migrationsによるスキーマのコード化・履歴管理へ移行。
